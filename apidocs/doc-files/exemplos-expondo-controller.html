Expondo controller com @ApiResource

Ganhe endpoints padronizados de CRUD, filtros, options, capabilities, estatísticas e exportação ao estender as bases canônicas do starter. Recursos read-only também são de primeira classe.

Exemplo recomendado (Baseline Resource-Oriented)

import org.praxisplatform.uischema.annotation.ApiGroup;
import org.praxisplatform.uischema.annotation.ApiResource;
import org.praxisplatform.uischema.controller.base.AbstractResourceController;

@ApiResource(value = ApiPaths.HumanResources.PESSOAS, resourceKey = "human-resources.pessoas")
@ApiGroup("human-resources")
public class PessoaController extends AbstractResourceController<
        PessoaResponseDTO,
        Long,
        PessoaFilterDTO,
        CreatePessoaDTO,
        UpdatePessoaDTO> {

    private final PessoaService service;

    public PessoaController(PessoaService service) {
        this.service = service;
    }

    @Override
    protected PessoaService getService() {
        return service;
    }

    @Override
    protected Long getResponseId(PessoaResponseDTO dto) {
        return dto.getId();
    }
}

@ApiResource já incorpora @RestController e @RequestMapping; não declare @RestController separadamente.

Defina sempre resourceKey como a identidade semântica estável do recurso e use @ApiGroup para organizar a documentação OpenAPI por contexto.

O que o contrato atual entrega

  • CRUD e discovery resource-oriented com detecção automática do base path via @ApiResource.
  • Snapshot contextual em /capabilities e /{id}/capabilities combinando suporte estrutural e disponibilidade atual.
  • Endpoints de options padrão e option-sources para fontes governadas no OptionSourceRegistry.
  • Endpoints estatísticos (group-by, timeseries, distribution, comparison) e exportação de coleções (/export).
  • Superfície de schema x-ui integrada a /schemas/filtered, /schemas/catalog e /schemas/domain.

Read-only (Views/@Immutable)

Use AbstractReadOnlyResourceController e AbstractReadOnlyResourceService para expor recursos somente leitura com x-ui.resource.readOnly=true.

O recurso continua com leitura, filtros, options, option-sources, capabilities e schema x-ui coerentes.
