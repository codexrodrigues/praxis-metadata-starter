O que é o Praxis Metadata Starter?

É o módulo canônico da plataforma Praxis para publicar contratos metadata-driven no backend Spring Boot. Ele enriquece o OpenAPI com x-ui, expõe superfícies estruturais (/schemas/filtered) e semânticas (/schemas/domain, /schemas/surfaces, /schemas/actions, /{resource}/capabilities), empacota o Praxis Cockpit (/praxis/cockpit) e fornece controllers, services e repositórios base para recursos REST, filtros, option sources, estatísticas e exportação de coleções.

O que é o Praxis Cockpit (/praxis/cockpit)?

O starter empacota automaticamente um cockpit visual em GET /praxis/cockpit (servido a partir de META-INF/resources/praxis/cockpit). Ele exibe o inventário navegável do serviço — áreas de domínio, recursos, endpoints, filtros, formulários, tabelas, gráficos, workflow actions e relacionamentos — além de uma gaveta de auditoria para os contratos JSON. Veja a demonstração ao vivo em praxis-api-quickstart.onrender.com/praxis/cockpit.

Qual a diferença entre /schemas/filtered, /schemas/catalog e /schemas/domain?

  • GET /schemas/filtered: é a superfície estrutural canônica para obter o schema de request ou response enriquecido com x-ui, idField, ETag e X-Schema-Hash.
  • GET /schemas/catalog: catálogo documental com resumos de operações, identidade visual, exemplos e links canônicos para os schemas estruturais.
  • GET /schemas/domain: catálogo semântico AI-operable com vocabulário de domínio, evidências, optionSources e governança (@DomainGovernance).
curl -i "http://localhost:8080/schemas/filtered?path=/api/human-resources/pessoas/all&operation=get&schemaType=response"

curl -i "http://localhost:8080/schemas/filtered?path=/api/human-resources/pessoas/filter&operation=post&schemaType=request"

Referência de API: ApiDocsController e DomainCatalogController.

Quando usar Resource, Surface, Action e Capability?

  • Resource (@ApiResource): operações principais do ciclo de vida do recurso (leitura, filtro, criação, atualização, exclusão, stats, exportação).
  • Surface (@UiSurface): descoberta semântica de uma experiência de UI (formulário parcial, visão analítica, sub-coleção relacionada) apontando para uma operação real.
  • Action (@WorkflowAction): comandos explícitos de negócio (aprovar, rejeitar, cancelar, executar em lote) com pré-condições e versão.
  • Capability (GET /{resource}/capabilities): snapshot agregado do que o recurso suporta estruturalmente e do que está permitido agora.

Como os grupos OpenAPI são resolvidos?

O starter combina grupos individuais por recurso, grupos agregados por contexto (@ApiGroup) e um fallback application. A resolução automática por path usa o best match mais específico disponível, com isolamento por grupo em escopo prototype.

Referências: DynamicSwaggerConfig e OpenApiGroupResolver.

Quando usar /options/filter, /options/by-ids e OptionSourceRegistry?

  • POST /{resource}/options/filter: para popular combos e autocomplete com busca paginada leve (OptionDTO{id, label}).
  • GET /{resource}/options/by-ids: para reidratar labels de valores já selecionados, preservando a ordem dos IDs.
  • OptionSourceRegistry (/{resource}/option-sources/{sourceKey}/options/*): para fontes remotas governadas, lookups de entidades corporativas (RESOURCE_ENTITY) e cascatas declarativas (dependsOn).

Referências: OptionDTO e Endpoints Overview.

Como modelar filtros com @Filterable?

Crie um DTO de filtro implementando GenericFilterDTO e anote os campos com @Filterable, informando a operação e, quando necessário, a relação no formato "a.b.campo". O builder converte o DTO em Specifications JPA automaticamente.

Referências: Filterable e filters-overview.

Como expor views e recursos read-only?

Use AbstractReadOnlyResourceService e AbstractReadOnlyResourceController. Os endpoints de leitura, filtros, options, capabilities e locate continuam disponíveis com x-ui.resource.readOnly=true; escritas retornam 405 Method Not Allowed por design.

Guia público: READ-ONLY-VIEWS.

Existe um runtime Angular oficial?

Sim. O repositório público praxis-ui-angular publica as bibliotecas @praxisui/* usadas para consumir /schemas/filtered e /{resource}/capabilities, renderizando formulários, tabelas, gráficos e ações a partir do vocabulário x-ui. 

# exemplo de instalacao em um host Angular novo
npm install @praxisui/core @praxisui/table @praxisui/dynamic-form @praxisui/crud

Guia público: Guia 03 - Frontend - Angular CRUD Completo.

Como funciona cache e ETag em /schemas/filtered?

O starter expõe ETag e X-Schema-Hash para revalidação condicional via If-None-Match. Quando nada muda estruturalmente, o endpoint responde 304 Not Modified sem trafegar o corpo novamente.

Referências: IfNoneMatchUtils e SchemaIdBuilder.

Quais projetos públicos fazem parte do ecossistema?

  • praxis-config-starter — Persistência de configurações de UI, AI registry, catálogo de APIs, regras de domínio e authoring governado.
  • praxis-api-quickstart — Host operacional de referência com PostgreSQL, segurança e demonstração pública do Praxis Cockpit.
  • praxis-ui-angular — Runtime oficial Angular (@praxisui/*).
  • praxisui.dev — Site oficial de exemplos, playgrounds e documentação da plataforma.
  • praxis-backend-seed-app — Projeto esqueleto para iniciar um novo serviço Spring Boot.
