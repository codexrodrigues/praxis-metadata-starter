Conceitos Fundamentais da Plataforma Praxis

Conceitos arquiteturais que sustentam o contrato metadata-driven e a fronteira entre recursos semânticos de backend, configuração governada e renderização dinâmica de UI.

Tópicos Conceituais

Conceito O que esclarece
UI Schema (@UISchema e x-ui) Vocabulário x-ui, precedência do CustomOpenApiResolver, validações e valuePresentation.
UI Schema vs Data Schema Separação entre contrato de dados/transporte e intenção de apresentação, edição e descoberta.
Self-describing APIs Como o backend publica estrutura (/schemas/filtered), semântica (/schemas/domain), surfaces, actions, capabilities e HATEOAS.
Schema-driven UI Geração e materialização de tabelas, formulários, filtros, diálogos de comando e gráficos a partir de contratos publicados.
Metadata-driven e Backend-agnostic Desacoplamento entre a semântica publicada em OpenAPI + x-ui e o runtime consumidor (@praxisui/*, cockpit ou agentes de IA).
Declarative UI Declaração de intenção (@UISchema, @UiSurface, @WorkflowAction) em vez de código imperativo repetitivo por tela.
Configuration-driven Development Fronteira entre metadados canônicos de código (praxis-metadata-starter) e variações governadas por tenant/usuário (praxis-config-starter).
Dynamic Component Rendering Resolução em runtime de controlType, valuePresentation, optionSource e surfaces semânticas no cliente e no /praxis/cockpit.
Headless UI and Design Systems Separação entre comportamento/semântica do contrato (x-ui) e identidade visual/componentes corporativos.
Rules Engines and Specifications Filtros dinâmicos (@Filterable + GenericSpecificationsBuilder), Json Logic canônico e determinações reativas.

Quando consultar esta seção

  • Para alinhar o vocabulário arquitetural da plataforma antes de modelar um novo domínio.
  • Para decidir se uma regra pertence ao contrato estrutural (praxis-metadata-starter), à configuração governada (praxis-config-starter) ou ao runtime visual (@praxisui/*).
  • Para complementar a árvore de decisão prática em Quando usar Resource, Surface, Action e Capability.
